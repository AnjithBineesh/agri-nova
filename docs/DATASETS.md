# External datasets: access, authentication and limitations

Agri Nova never fabricates observations. Each dataset has its own adapter in
`backend/app/earth_observation/`, and every value is stored with its dataset, product ID, unit,
date, spatial and temporal resolution, quality flag, data type and source URL.
The **Earth Insights** page and `GET /api/farms/{id}/earth-data` show each dataset's status.

| Status | Meaning |
|---|---|
| `complete` | Retrieved and stored |
| `pending` / `processing` | Submitted to NASA AppEEARS. Results are ingested automatically on the next status check |
| `not_configured` | Earthdata credentials are missing |
| `failed` | Upstream error; the message says why. No substitute values are created |
| `no_data` | Request succeeded but no usable (quality-screened) values were returned |
| `not_integrated` | Adapter interface exists; retrieval is planned |
| `demonstration` | Synthetic values loaded on explicit request (`ENABLE_DEMO_DATA=true`). Labelled on every screen and in reports |

## 1. NASA POWER (integrated, no credentials)
* API: `https://power.larc.nasa.gov/api/temporal/{monthly|daily}/point`, community `AG`.
* Parameters: `T2M, T2M_MAX, T2M_MIN, PRECTOTCORR, RH2M, ALLSKY_SFC_SW_DWN, WS2M`.
* Retrieved: monthly values for the last 10 complete years (climatology, trends) and daily values
  for the last 2 years (heat-stress days).
* Resolution: about 0.5° × 0.625° for meteorology and 1° for solar, so values describe a grid cell
  tens of kilometres wide. This is a weather/climate estimate, not a field measurement.
* Monthly precipitation in mm/day is converted to mm/month using the units POWER returns.

## 2. GPM IMERG (integrated, Earthdata token)
* Service: GES DISC "Giovanni in the Cloud" time-series API
  (`https://api.giovanni.earthdata.nasa.gov/timeseries`) with an Earthdata Login bearer token.
* Variables: `GPM_3IMERGDF_07_precipitation` (Final Run, gauge-adjusted, about 3.5 months latency) for
  about 3 years, then `GPM_3IMERGDL_07_precipitation` (Late Run, provisional, about 14 h latency) for the
  most recent period only. Late Run values are flagged `late_run_provisional`.
* 0.1° (~11 km). Monthly totals are built only from complete months. The climate profile uses IMERG
  rainfall once at least 12 complete months covering every calendar month are available; otherwise it
  falls back to POWER and says so.
* Token: set `EARTHDATA_TOKEN`, or `EARTHDATA_USERNAME` and `EARTHDATA_PASSWORD` (a token is then
  requested from `urs.earthdata.nasa.gov/api/users/find_or_create_token`). Your Earthdata profile
  must have the GES DISC application authorised.

## 3–8. AppEEARS-based products (integrated, Earthdata username and password)
AppEEARS (`https://appeears.earthdatacloud.nasa.gov/api`) point requests are asynchronous. A refresh
submits two tasks per farm:

1. **Time series** at the farm point for the last 2 years:
   * **SMAP** `SPL3SMP_E` surface soil moisture (9 km; `retrieval_qual_flag` bit 0 marks
     "recommended") and `SPL4SMGP` surface and root-zone moisture (9 km, 3-hourly, averaged to daily;
     labelled *model estimate* because it is land-model output with SMAP assimilation).
   * **MODIS** `MOD13Q1.061` NDVI/EVI (250 m, 16-day). Only pixel reliability 0 (good) or 1 (marginal)
     is kept.
   * **Landsat** via `HLSL30.020` and **Sentinel-2** via `HLSS30.020` (30 m). NDVI is calculated from
     B05/B04 and B8A/B04; observations with Fmask cloud, adjacent cloud, shadow, snow/ice or water
     are removed.
   * **ECOSTRESS** `ECO_L2T_LSTE.002` LST (cloud mask applied) and `ECO_L3T_JET.002` daily ET (70 m;
     irregular ISS overpasses).
2. **Terrain**: **SRTM** `SRTMGL1_NC.003` on a 3 × 3 grid at 1 arc-second spacing around the farm.
   Slope is derived with Horn's method.

Product versions change over time. Check the current identifiers with
`GET https://appeears.earthdatacloud.nasa.gov/api/product` and override them in `.env` if needed
(`SMAP_L3_PRODUCT`, `SMAP_L4_PRODUCT`, `MODIS_VI_PRODUCT`, `HLS_*`, `ECOSTRESS_*`, `SRTM_PRODUCT`).

## Interface-only datasets
* **ERA5** (`era5_service.py`): planned via the CDS `reanalysis-era5-single-levels-timeseries`
  dataset with `CDS_API_KEY`. POWER already supplies the variables the engines need.
* **FAO GAEZ v5** (`gaez_service.py`): planned raster sampling of suitability indices. Crop
  requirements currently come from FAO ECOCROP (see below). GAEZ is an FAO/IIASA product, not a
  NASA dataset.

## US-only datasets
SSURGO/STATSGO2, CDL, PRISM, NAIP, NLCD, CoCoRaHS, NASS QuickStats, NWIS, OpenET and LANDFIRE are
**not** required. The adapter pattern allows them to be added for farms inside their coverage.

## Crop knowledge base
`backend/app/agriculture/data/crops.json` is generated by `backend/scripts/build_crop_database.py`:
* temperature, killing temperature, annual rainfall, pH, texture, drainage, fertility and salinity
  ranges are taken directly from the **FAO ECOCROP** database (as distributed in the Recocrop R
  package);
* crop coefficients (Kc) are from FAO-56 Table 12, rooting depths from FAO-56 Table 22, and
  seasonal water needs from FAO Irrigation Water Management Manual 3;
* nutrient removal per tonne, residue:product ratios, %N from fixation and residual N credits are
  **indicative coefficients** (IPNI/IFA tables; Herridge et al. 2008; Peoples et al. 2009). They are
  labelled as such and researchers can edit them (`PUT /api/crops/{slug}`).

## Soil information
Satellites do not measure soil pH or available N, P and K. Soil values come only from farmer
entry or a confirmed laboratory report. Values extracted by OCR stay `pending` until the user
reviews and confirms them.
